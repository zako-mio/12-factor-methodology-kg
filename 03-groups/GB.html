节点目录 (12 个)

节点 ID名称来源阶段简介
ag-nl2tool自然语言→工具调用Agent基础Agent 构建中最常见也最强大的模式，就是把用户的自然语言请求翻译成结构化的工具调用对象，让 LLM 既能推理任务又能驱动系统真正执行动作。
ag-prompts掌控你的 PromptAgent基础不要把 prompt 工程外包给框架，这是本因子最核心的一句话：prompt 必须由你亲自掌控，而不是交给黑盒。
ag-context掌控上下文窗口Agent进阶你不需要拘泥于标准消息格式来向 LLM 传递上下文：『任何时刻，你给 LLM 的输入本质上就是：到目前为止发生了什么，下一步是什么』。
ag-tools工具即结构化输出Agent基础工具不需要复杂，其核心就是『LLM 输出的结构化数据，用于触发确定性代码』——工具本质上只是结构化输出。
ag-state统一执行/业务状态Agent进阶在 AI 世界之外，许多基础设施系统也倾向于把『执行状态』与『业务状态』分开管理；对 AI 应用而言这可能需要跟踪当前步骤、下一步、等待状态、重试计数等。
ag-pause启动/暂停/恢复Agent进阶Agent 只是程序，我们理应对它们如何被启动、查询、恢复、停止有明确预期——这就是 Launch/Pause/Resume 的诉求。
ag-human工具调用联系人类Agent进阶LLM API 默认依赖一个高风险的『首个 token』选择：返回纯文本，还是返回结构化数据，赌注全押在这一枚 token 上。
ag-control掌控控制流Agent进阶如果你掌控自己的控制流，就能做很多有趣的事：为你的特定用例构建自己的控制结构，而不是被框架规定死。，属于该因子的基础原则，应在设计中显式落实。
ag-errors压缩错误进上下文Agent进阶Agent 的一大好处是『自愈』：对短任务，LLM 调用工具失败时，好的模型相当有机会读懂错误消息或堆栈并想出在后续调用中改什么。
ag-small小而专注的 AgentAgent高级与其构建想包办一切的单体 Agent，不如构建小而专注、一件事做到位的 Agent——Agent 只是更大的、基本确定性系统中的构件。
ag-trigger随处触发Agent高级让用户能从 slack、email、sms 或其他任何他们喜欢的渠道触发 Agent，并让 Agent 通过同样的渠道回复——在用户所在的地方遇见他们。
ag-reducer无状态 ReducerAgent高级第 12 条：把 Agent 建模成无状态的归约器（stateless reducer）。原文自己承认：写到这已超 1000 行 markdown，这条主要是图个乐。
