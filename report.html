五、反思 / 分析 / 建议

用户中途补充"工具融入"需求验证了脚本链价值：数据更新 → 重跑 gen-*.py 即全量再生成（约 10 秒），无需手改任何页面。这正是保留 07-checkpoint 的意义。
硬编码文案陷阱：gen-index.py 中 3 处"15 组/34 节点"硬编码未随数据变化自动更新。教训：生成脚本中的统计类文案应一律从 DAG meta 动态取数，不写死数字（已修复）。
MD 镜像曾被遗漏：子Agent 生成的 6 个脚本未覆盖 06-md。教训：委派 prompt 应显式列出全部交付物清单并逐一核对。
  • 工具节点是加分项：create-12-factor-agent 模板、walkthroughgen、工作坊材料让图谱从"纯理论原则"升级为"可实操方法论"。
  • 桥接主题设计是灵魂：10 个主题经 prerequisite 构成"打通路径"，variant 标注语义对应——这是两套方法论合并的价值核心。
后续阶段反思：
6. 用方法论审查产物本身是高效的质量手段：用户要求"应用 12 Factor 原则检查图谱库"——立刻抓出 3 个常规验证发现不了的缺陷（无 .git、硬依赖外部 vendor、硬编码路径）。可再构建性（V）与依赖显式化（II）的审视视角可直接复用。
7. 构建可复现性必须防"环境漂移"：Actions 重建产生额外提交的根因是 gen-md.py 用 set 无序遍历。"重建后 diff 为零"是验证可复现性的黄金标准，也天然防 Actions 重建循环。
8. 委派内容的"深度预期"要显式设定：第一轮 17KB 摘要级（用户不满），第二轮明确"每节点 1500-3000 字 + 忠实原文 + 保留技术细节"产出 105KB。内容类委派 prompt 必须显式给出字数下限与忠实度要求。
9. 精选复制 vs 全量复制的决策需量化论证：全量 109M（80% 低价值内容）vs 精选 2.3M（100% 方法论+工具核心），用"对学习实践的价值"逐类分析。
10. GitHub workflow scope 的坑：首次推送含 .github/workflows/ 会被 GitHub 拒绝（token 需 workflow scope）；且授权走代理才能成功（境外访问）。
11. 用户期望的动态演进：从"合并方法论"→"上传分享"→"内容详细准确"→"融入源码资产+AI 可调用索引"。脚本链+数据驱动架构使每次演进都是增量（改数据→重跑→推送），而非推翻重来，这是本任务最大的架构红利。
